# RFC 001: End-to-End Encryption & Key Management Architecture

## 1. Summary

This RFC defines the E2EE protocol for 1-to-1 and group chats, ensuring zero-knowledge message delivery where the server only acts as a blind relay.

## 2. Key Generation & Exchange Protocol

- **Identity Keys:** Upon registration, each client generates an ECC (Elliptic Curve Cryptography) Key Pair.
- **Public Key Directory:** Public keys are registered on the backend under the user's UUID.
- **Session Key Setup (ECDH):**
  1. Sender requests Recipient's public key from `/api/v1/users/:id/public-key`.
  2. Sender computes a shared secret using Diffie-Hellman key exchange.
  3. Messages are encrypted locally using **AES-GCM-256** with a unique Initialization Vector (IV).

## 3. Group Key Distribution

- Group creators generate a symmetric **Group Master Key (GMK)**.
- The GMK is encrypted individually for each member using their respective public key and delivered via a secure socket event (`group_key_distribution`).
